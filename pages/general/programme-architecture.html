Programme Architecture — NEF Public Hiring Package

Date: 2026-06-01 Purpose: define the minimum coherent public package for presenting the housing research programme to NEF as a hiring case rather than as a raw research dump.

Objective

Turn the existing NEF-facing material into one public-facing package that a hiring reader can navigate in one sitting:

  1. understand the policy claim,
  2. see that it is backed by real empirical and theoretical work,
  3. inspect as much depth as they want without getting lost in internal process,
  4. come away with a clear picture of role-fit.

Governing Decision

Do not publish this repository directly as the public package.

This repository contains internal review ledgers, adversarial packets, operating-layer notes, archived drafts, and other material that is useful for research production but wrong for a hiring-facing public surface. The correct approach is a separate curated public repository whose content is exported from the canonical sources here.

Public Audience

The package must work for three overlapping readers:

  1. NEF hiring panel members deciding whether the candidate is worth interviewing.
  2. NEF researchers who may want to inspect the analytical depth behind the application.
  3. Policy-adjacent readers who will only read one landing page, one blog post, or one abstract page.

The package therefore needs a strict reading gradient from shortest to deepest.

Required Public Surfaces

The public package should contain exactly these layers.

Layer 1: Entry

  • Landing page: one-screen overview of who Carlos is, what the programme does, and where to start.
  • Cover letter page: the application letter as a readable web page, not just a file attachment.
  • Abstracts dossier: one page that summarizes the five-paper programme and routes readers to the full texts.

Layer 2: Fast persuasion

  • Housing policy paper: Breaking the Benchmark.
  • Empirical paper: Fiscal Capture in the UK Private Rented Sector.
  • One or two public explainers/blog posts written in accessible register.

These are the highest-yield surfaces for NEF hiring purposes.

Layer 3: Deeper foundation

  • Rent as Reproduction Cost.
  • Labor Power as Numéraire.
  • A Progressing Problemshift.

These should be available, but not forced on a first-pass reader.

Content Selection Rule

The public repo should be selective.

Include

  • Cover letter.
  • Landing page.
  • Abstracts dossier.
  • Full HTML versions of the five papers.
  • PDF downloads for the five papers.
  • One LHA empirical explainer.
  • One LPN or welfare-framework explainer only if it helps rather than intimidates.

Exclude

  • external_review_*
  • _temp_agent/
  • _backups/
  • internal ledgers, stale prompts, model-lock notes, handoffs, and operating diagnostics
  • archived drafts and superseded packets
  • any file whose main purpose is process rather than argument

Reading Path Design

The public site should give readers three explicit routes.

  1. Two-minute route: landing page -> cover letter -> abstracts dossier.
  2. Policy route: landing page -> Breaking the Benchmark -> Fiscal Capture -> selected blog.
  3. Deep theory route: landing page -> Rent as Reproduction Cost -> Labor Power as Numéraire -> A Progressing Problemshift.

This avoids the current problem where good material exists but the order of entry is implicit.

Render Matrix

Minimum HTML outputs required for a first public release:

  1. index.html — landing page.
  2. cover-letter.html — rendered NEF cover letter.
  3. abstracts/index.html — rendered abstracts dossier.
  4. papers/breaking-the-benchmark.html
  5. papers/fiscal-capture.html
  6. papers/rent-as-reproduction-cost.html
  7. papers/labor-power-as-numeraire.html
  8. papers/progressing-problemshift.html
  9. blogs/lha-benefit-capture.html
  10. optional: blogs/lpn-explainer.html

Every paper page should also expose a PDF download link.

Why a separate repo:

  • cleaner public history,
  • no risk of leaking internal review material,
  • simpler GitHub Pages deployment,
  • easier to maintain a professional front door.

Export Rule From This Repo

This repository remains the canonical authoring environment.

  • papers/*.qmd remain the manuscript SSOT.
  • blog/*.qmd remain the explainer SSOT.
  • nef_abstracts/*.md remain the abstract SSOT.
  • papers_NEF/ remains a generated staging layer, not the final public site.

The public repo should be updated by exporting curated content from those canonical sources, not by hand-editing copies after publication.

Release Order

The highest-value release sequence is:

  1. landing page,
  2. cover letter,
  3. abstracts dossier,
  4. policy paper html,
  5. fiscal-capture html,
  6. one blog post,
  7. remaining theory papers.

This sequence gets the hiring-facing argument live early, without waiting for the deepest theory surfaces to become the entry point.

Acceptance Criteria

The package is ready for publication only when all of the following are true:

  1. Every link on the cover letter resolves.
  2. The abstracts dossier links to all five full papers.
  3. All five papers have public html pages and downloadable pdfs.
  4. The landing page makes the reading order explicit.
  5. No internal-review or operating-layer file is reachable from the public navigation.
  6. The first screen makes clear why this package is relevant to NEF specifically.

Immediate Next Build Tasks

  1. Create the separate public repository skeleton.
  2. Add a Quarto website config and landing page.
  3. Convert the cover letter and abstracts dossier into site pages.
  4. Render missing html pages for the three papers that currently lack them.
  5. Select and render the one or two blog posts that sharpen the hiring case.
  6. Add a small deployment script or task that exports the public package deterministically.

Strategic Note

For NEF hiring purposes, the package should foreground the housing policy and empirical papers, not the full heterodox architecture. The theory should remain available as proof of depth, but the public entry sequence should start with practical policy relevance and quantitative evidence.
